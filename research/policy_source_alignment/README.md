# 원문 조건을 읽고, 틀린 규칙과 저장 판단을 고치기

이전 실험에서 금액 사실을 고쳐도 정책 규칙의 AND/OR·급여 제외·환산식 오류가 남았습니다. 이번에는 **원문에서 조건 후보를 만들고 → 연결 의미를 읽고 → 신청자 사실을 대조하고 → 변경된 정책으로 저장 판단을 갱신하는 과정**을 구현했습니다.

역사적 서울경제 제출물과 별도로 진행한 개인 후속 연구입니다. AI 보조로 구현·실험·잠정 주석을 작성했으며, 이번 신규 모델 학습은 0회, 독립 사람 판독은 0명입니다. 고객 비공개 문서·운영 데이터는 사용하거나 공개하지 않습니다. 공식 공개 자료의 선택 조항과 작성한 가상 주장만 사용합니다.

## 실제로 반복한 과정

1. 이전에 관측한 48개 주장을 개발 자료로 삼았습니다. 원문 숫자·단위·위치에서 조건 후보를 만들고 모델이 후보 ID만 조합하게 했습니다. 최초 정책 응답 24개는 모두 보류했습니다.
2. 일반 규칙 작성과 신청자 판단을 구분하고 AND/OR 예시를 추가했습니다. 개선됐지만 연결 오류가 남았습니다. 정답 규칙을 주지 않고 제한 문법 해석기와 다른 결론을 내는 반례 7개를 제시했지만 **점수 개선은 없었습니다**.
3. 중첩 배열 대신 `ALL / ANY`와 조건 ID로 출력하게 했습니다. 이 지시·표현 묶음이 관측 자료의 정책 오류를 해결했습니다. 급여 부정의 병렬 구조, 중위소득 비율, 부모 금액을 거주 기간으로 읽는 오류도 주장 자체의 근거로 보정했습니다. 개발 48개는 두 모델 모두 답과 사실이 일치했습니다. **관측한 자료에 맞춘 결과**입니다.
4. 방법을 고정한 뒤 처음 읽는 창원·수원 공식 안내의 4개 선택 범위, 가상 주장 20개를 평가했습니다. 연령 표기를 후보로 만들지 못해 두 모델 모두 **10개 정답·10개 보류**였습니다. 최초 결과를 보존한 채 연령 문법을 확장했고 같은 자료 재검사는 각각 20/20이었습니다.
5. 확장 방법을 고정한 뒤 새로운 기관인 국민연금공단의 2개 연령 조항, 가상 주장 10개에서 각각 10/10을 확인했습니다. 다른 기관·다른 나이 경계의 확인이며, **연령 문법 전체나 전체 수급 자격의 일반화 검증은 아닙니다**.
6. 기존 서울 보증료 공고의 전후 버전에 자연어 주장 18개를 연결했습니다. 가입일·신청일·부모의 가입일·금액·정보 누락을 읽고, 정책 변경에 따른 판단 변화와 기존 저장 오답을 따로 검사해 실제 값을 갱신했습니다.

## 핵심 결과와 해석

| 비교 | Qwen | 공개 Kanana | 평가 성격 |
|---|---:|---:|---|
| 개발 48개: 이전 규칙+금액 보정 | 33/48 | 32/48 | 이미 관측한 자료 |
| 개발 48개: 후보 연결+사실 보정 | 48/48 | 48/48 | 사후 개발 결과 |
| 창원·수원: 최초 고정 방법 | 10/20, 보류 10 | 10/20, 보류 10 | 새 기관 첫 적용 |
| 같은 자료: 연령 확장 후 | 20/20 | 20/20 | 실패를 본 뒤 재검사 |
| 국민연금공단: 확장 후 첫 적용 | 10/10 | 10/10 | 새 기관, 연령 2개 범위 |
| 저장 답을 그대로 유지 → 갱신 | 6 → 18/18 | 4 → 18/18 | 기존 전후 문서에 새 자연어 주장 |

**조건 후보를 규칙으로 조합한 비교군도 같은 최종 점수를 냈습니다.** 모든 개선을 LLM의 이해력 향상으로 귀속하지 않습니다. 특히 갱신 실험에서 모델 자체의 슬롯 일치는 Qwen 18/18, Kanana 1/18이고, 원래 모델 슬롯을 실행한 답은 각각 18/18, 3/18입니다. Kanana의 최종 18/18은 명시적 가입일·금액을 읽는 제한 문법 보정의 결과입니다. 학습 성능·독립 사람 검증·새 기법의 학술적 독창성을 입증한 실험으로 표현하지 않습니다.

## 구현과 공개 경계

- 원문 후보: [candidates.py](candidates.py), [age_extension.py](age_extension.py). 원문은 숫자와 연산자의 출처이며, 후보의 존재가 논리적 충실성을 보증하지 않습니다.
- 모델 연결: [explicit_logic.py](explicit_logic.py). 한 단계 ALL/ANY만 표현합니다. 혼합된 중첩 예외는 지원하지 않습니다.
- 주장 검증: [claim_alignment.py](claim_alignment.py). 명시된 본인·가구의 일부 금액·비율·급여 문법만 다룹니다.
- 변경과 갱신: [revision_chain.py](revision_chain.py). 가입일별 상한, 정보 누락, 기존 오답을 함께 처리합니다. 기존 원문의 추출된 계약을 재사용합니다.
- 사용 범위: [scoped_reader.py](scoped_reader.py). 호출자가 선택 조항·필드·원문 버전을 명시해야 하며 전체 사업 판정 요청, 바뀐 원문, 일부 미지원 논리는 보류합니다. 이는 명시적 사용 제한이지 모든 문장에 대한 의미 검증 증명은 아닙니다.
- 재현: [verify.py](verify.py). 최초 실패, 저장 응답, 참조, 점수, 동결 시점, 이전 연구 파일을 검사합니다.

전문·원시 응답의 산문은 재배포하지 않습니다. 공식 주소·원본/추출문 해시·선택 위치·정제 구조·가상 주장·코드·측정 결과를 공개합니다. 논문 수준의 일반화 주장을 하려면 독립 사람의 원문 판독과 더 넓은 표본이 필요합니다. 현재 공개 결과는 그 검수를 대신하지 않습니다.
