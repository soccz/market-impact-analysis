# 한국어 정책의 조건을 읽는 모델은, 근거가 달라져도 같은 판단을 유지하는가

정책·기사·시장을 연결하던 개발에서 발견한 판독 문제를 **대상·예외·시점·버전·확정성에 따른 주장 판독**으로 좁힌 개인 NLP 연구입니다. 앞선 규칙 기반 조건 추출에서 놓친 범위를 지시 모델이 읽을 수 있는지 실제로 실행했습니다. 설명을 구조화한 뒤의 개선뿐 아니라 근거 혼입, 근거 가림, 다른 기관 적용에서 나타난 역효과도 보존합니다.

설계·코드·합성 예문·공식 문서의 잠정 정답에는 AI 지원을 사용했습니다. **독립 사람 판독 0명, 이번 실험의 새 모델 학습 0회**입니다. 전체 신청 자격이나 실제 지급 결정을 대신하지 않습니다. 문서에서 수동 선택한 근거와 특정 주장 사이의 관계를 평가하며, 전체 문서 검색 성능은 측정하지 않습니다.

## 연구 질문과 실행한 수정

1. **이유를 말하면 조건도 정확히 읽는가?** 가상 개발 예문 24개를 고정하고 두 로컬 모델을 실행했습니다. `140 ≤ 120`을 참으로 쓰거나, 규칙을 불충족이라고 설명하면서 최종 답은 충족이라고 하는 실패를 확인했습니다.
2. **대상·적용 규칙·확정 상태를 나누면 나아지는가?** 개발 오류를 보고 구조화 프롬프트를 고정한 뒤 제주 원문과 별도 구성 사례에서 평가했습니다. Qwen의 제주 기본 정답은 11/18에서 16/18로 증가했지만 다른 사업 문장 혼입에서는 9/18로 내려갔습니다. 근거를 가린 18개 중 8개에는 잘못된 확정 답을 냈습니다.
3. **근거의 충분성을 먼저 확인하면 해결되는가?** 해당 사업·버전의 근거가 있는지 먼저 판독하도록 하고, 출력 근거 ID를 입력 ID로 제한했습니다. 이 결합 방식은 Qwen의 제주 혼입 정답을 10/18로 만들었지만 기본 정답은 7/18이었습니다. 새 기관인 인천에서도 기본 정답이 9/12에서 7/12로 감소했습니다. 미확인을 많이 출력하는 것만으로는 개선이 아닙니다.
4. **모델의 추론 모드와 계산량을 바꾸면 무엇이 달라지는가?** 같은 프롬프트와 같은 출력 한도로 모드 유무를 비교했습니다. 후속 12개에서 추론 모드의 정상 출력 기준 정답은 2,048 설정에서 1개, 샘플링과 4,096 설정에서는 2개였습니다. 한도 소진은 각각 11개·9개였습니다. 같은 설정의 비추론 비교군은 모두 6개 정답이었습니다. 이 결과는 해당 실행 설정의 실패이며 모델의 최적 성능을 뜻하지 않습니다.
5. **출력 형식을 고친 것과 내용을 더 잘 읽은 것을 구별할 수 있는가?** 기본 프롬프트를 유지하고 근거 ID만 입력에 있는 값으로 제한하는 180회 비교를 추가했습니다. Qwen의 제주 혼입에서는 정상 출력 기준 정답이 3/18에서 8/18로 늘었지만, ID 오류를 무시한 의미 답의 정답은 둘 다 8/18이었습니다. 없는 ID 출력 10개를 없앤 효과와 내용 판독의 개선을 구별했습니다. 인천에서도 동일한 분리를 확인했으며, Kanana에는 일관된 이득이 없었습니다.

이 흐름은 명제 관계 분류를 넘어, **근거 선택 → 적용 범위 → 연산 → 확정 가능성 → 최종 답** 중 어디에서 오류가 발생하는지 드러내기 위한 것입니다. 모델이 만든 설명은 그 자체로 검증된 증명이 아닙니다.

## 모델 계보까지 확인하기

[models.json](models.json)에 모델·가중치·템플릿 해시와 상속 설정을 기록했습니다. 최초 설치된 Kanana 계열 로컬 모델은 공개 배포본과 텐서 내용이 달라, 그대로 공식 Kanana의 성능이라고 부르지 않습니다. 기존 결과를 남기고 공개 배포본의 LFS 해시와 일치하는 별도 Q4_K_M 가중치로 다시 비교했습니다. 이 가중치도 제3자 양자화본이며 원본 정밀도 모델이 아닙니다.

Qwen3.5:9b는 Ollama 레지스트리의 모델 계층 해시를 대조했습니다. [Qwen 모델 문서](https://huggingface.co/Qwen/Qwen3.5-9B)와 [Kanana 원 모델 문서](https://huggingface.co/kakaocorp/kanana-1.5-8b-instruct-2505)를 연결합니다. 모델 계보 차이가 성능 차이의 유일한 원인이라는 주장은 하지 않습니다. 새 공개 Kanana 등록 후 첫 출력 파싱이 실패해 종료 토큰을 지정했으며, 유효한 평가 출력이 나오기 전에 수정했습니다.

최초·구조화·근거 충분성 방식은 온도 0, seed 20261001, 문맥 8192, 출력 한도 256입니다. 최초 Qwen은 추론 모드를 끈 텍스트 입력입니다. 추가 모드·디코딩 실험은 별도 기록의 출력 예산과 설정을 사용합니다. 모든 방법에서 정답·근거 위치·형식화 정답 메타데이터를 모델에 보내지 않습니다.

추론 응답 중에는 3,508자의 추론 필드와 최종 답을 반환했는데 API `eval_count`는 15인 사례가 있었습니다. 이 계수를 전체 생성 토큰 비용으로 단정하지 않습니다. 원래 API 계수·추론 문자 수·종료 사유를 보존하고, 비교 그림에는 관측한 요청 시간의 중앙값을 사용합니다. 단일 실행·공유 실행 환경의 벽시계 시간이며 정밀한 처리량 벤치마크는 아닙니다.

## 지표 해석

- **정상 출력 기준 정답:** 유효한 JSON·입력에 존재하는 비어 있지 않은 근거 ID 목록을 반환하면서, 지지 / 반박 / 근거로 확정 불가가 잠정 기준과 같은가. 결과 파일의 `correct` 및 기본 표의 정답 수입니다.
- **형식 오류를 무시한 의미 정답:** 파싱된 의미 답만 잠정 기준과 비교합니다. [근거 ID 분리 실험](results/citation/summary.json)의 `raw_decision_correct`로 따로 제공하며 정상 출력 정답과 섞지 않습니다.
- **정답+필요 근거:** 의미 정답과 함께 적어도 하나의 충분 근거 집합을 포함하는가. 추가로 고른 유효 문장도 허용하므로 최소 근거 선택 정확도와 같지 않습니다. 불필요한 인용 수를 따로 기록합니다.
- **잘못된 확정:** 틀린 지지·반박. 특히 기준이 미확인인데 확정한 경우를 별도로 셉니다.
- **시스템 보류:** 잘못된 JSON·없는 근거 ID·비어 있는 근거 목록·출력 한도 소진 등 출력 계약 실패. 의미상의 ‘미확인’과 다릅니다.
- **쌍별 변화:** 기본·혼입을 모두 맞힌 수, 방법을 바꿔 얻은 정답과 잃은 정답을 기록합니다.

가림 통제에서 선택하는 실험용 가림 문구는 정보가 제공되지 않았음을 표시하는 인용이지 정책 사실의 긍정·반박 근거가 아닙니다. 모델 두 개의 합의나 설명의 단순 수식 검사는 잘못된 답을 모두 제거하지 못했습니다. 검사 때문에 맞은 답을 잃은 경우도 보존합니다.

표본은 기관 두 곳의 일부 조건에 한정되며 서로 연결된 주장·변형이 많습니다. 이를 독립 표본처럼 합쳐 유의확률이나 한국어 정책 전체의 정확도를 주장하지 않습니다. 원문이 모델 사전학습에 포함됐는지도 배제할 수 없습니다. 새 문서·독립 사람 판독과 구별된 실행 기록입니다.

## 잠정 주석의 해석도 다시 점검하기

‘실제 정책 결과를 확정하지 못한다’와 ‘이 근거만으로 확정할 수 있다는 주장이 틀렸다’는 질문의 층위가 다릅니다. 개발 예문 한 개와 제주 가능성 주장 한 계열에는 두 판독 관례가 가능하다고 보고, [주석 민감도](results/annotation_sensitivity.json)를 추가했습니다. 기존 미확인 정답을 반박으로 읽는 경우의 점수도 계산하되 원래 정답과 최초 예측은 바꾸지 않았습니다. 관측 후 선택한 제한적 점검이며 사람의 독립 재판정이 아닙니다.

[class_diagnostics.json](results/class_diagnostics.json)에는 의미 클래스별 혼동행렬·정밀도·재현율, 확정 가능한 주장에 대한 잘못된 미확인, 출력 비율을 기록합니다. 세 정답 클래스가 모두 존재할 때만 macro F1을 제공합니다. 가림처럼 정답이 전부 미확인인 묶음에 세 클래스 성능처럼 보이는 F1을 붙이지 않습니다.

## 선행 연구와 이 기록의 위치

현상별 행동 검사는 [CheckList — Ribeiro et al., ACL 2020](https://aclanthology.org/2020.acl-main.442.pdf), NLI의 숫자·부정 등 취약점 진단은 [Naik et al., COLING 2018](https://aclanthology.org/C18-1198/)과 연결됩니다. 근거를 고르는 평가와 근거가 실제 결정에 기여하는지의 평가는 [ERASER — DeYoung et al.](https://arxiv.org/abs/1911.03429)에서도 구분됩니다. 설명의 그럴듯함을 충실성과 혼동하지 않는다는 문제는 [Jacovi & Goldberg, ACL 2020](https://aclanthology.org/2020.acl-main.386/)를 참고했습니다.

이 기록은 이들 방법을 새 알고리즘으로 재명명한 것이 아닙니다. 개인 개발에서 생긴 문제를 한국어 정책의 **사업·수혜자·신청 시점·버전·지급 역할**로 구체화하고, 원문 위치에서 첫 출력과 실패·수정 이력까지 연결한 소규모 실행입니다. 인용 ID의 일치, 전체 근거 가림, 최종 답과 설명 사이의 모순만으로 모델 내부 추론의 인과적 충실성을 증명하지 않습니다.

## 재현

Python 3.12, pyhwp, PyMuPDF, requests와 Ollama를 사용했습니다. [requirements.txt](requirements.txt)는 분석·원문 재구성 환경입니다. 모델 가중치와 원문 전체는 저장소에 포함하지 않습니다.

```bash
pip install -r requirements.txt
python verify.py
python fetch_sources.py --cache /tmp/policy-scope-sources
python prepare_inputs.py --cache /tmp/policy-scope-sources
```

`verify.py`는 공개된 첫 출력에서 모든 점수를 다시 계산하고 이전 연구 산출물의 해시를 확인합니다. `fetch_sources.py`는 지정한 세 원본만 내려받으며 해시가 달라졌으면 멈춥니다. `prepare_inputs.py`는 공개 주석 기록을 바꾸지 않고 비공개 입력을 재구성합니다. `verify.py --cache <원실행 캐시>`는 원문 위치·원요청 해시·원출력의 공개용 변환까지 확인합니다. 원실행 캐시에는 공개하지 않은 전체 모델 응답이 필요합니다.

새 추론은 기존 출력 폴더를 덮어쓰지 않고 별도 경로에 저장합니다. 모델 이름만 같다고 같은 가중치인 것으로 간주하지 않습니다. 아래 예는 현재 로컬에 동일 Qwen 가중치가 준비되어 있을 때의 별도 재실행입니다.

```bash
python extension_infer.py --inputs /tmp/policy-scope-sources/replication_inputs.json \
  --output /tmp/policy-scope-replay/qwen-baseline --model qwen --method baseline
python thinking_infer.py --inputs /tmp/policy-scope-sources/followup_inputs.json \
  --output /tmp/policy-scope-replay/qwen-thinking
```

저장 출력의 재집계 일치와 모델의 재추론 일치는 다른 검증입니다. 한 번의 seed나 작은 재실행으로 환경 간 완전 재현성을 보장하지 않습니다. [사람 검수 양식](human_review.tsv)의 42행은 아직 비어 있습니다. 검수자는 모델 답을 보기 전에 원문에서 지정한 주장만 독립 판독하고, 판단 근거와 모호함을 기록해야 합니다. AI가 이를 사람 검수로 대신 채우지 않습니다.
