# 금액 표기와 문맥 역할을 분리하는 정책 판독 v4

soccz의 개인 후속 연구 · 2026년 10월 1일 갱신. v3의 높은 합성 점수가 단위 표기 변경에서 무너진 뒤, **예문을 늘리는 것과 입력 표현 자체를 바꾸는 것은 어떻게 다른가?**를 비교합니다. 설계·코드·합성 자료·분석에는 AI 지원을 사용했습니다. 고객 원자료·납품 구현을 사용하지 않았습니다.

## 문제에서 개입으로

v3 학습의 기준 금액 960개는 모두 ‘만원’ 표기였습니다. 단위만 보강하면 원 단위 반례의 공동 일치가 0 → 26.10%로, 대상 문맥만 보강하면 다른 사업 반례가 0.81 → 38.66%로 개선됐습니다. 두 보강을 합쳤을 때는 그 효과가 함께 유지되지 않았습니다.

이번에는 파서가 인식한 모든 금액을 문맥 모델 입력에서 `0원`으로 통일합니다. 예컨대 `50만 원`과 `500,000원`은 같은 문자열로 들어갑니다. 실제 값과 원문 위치는 별도 기록에 보관하고, 모델이 예측한 금액 역할·근거 범위를 원문에 복원합니다. 이 별도 기록은 문맥 인코더의 수치 입력 특징이 아닙니다. **문맥 역할을 읽는 것과 값을 계산하는 것을 나누는 개입**입니다.

정답 라벨이나 금액의 기준·후속 역할을 보고 바꾸지 않습니다. 같은 파서로 인식한 모든 금액에 같은 변환을 적용합니다. 정답 구절의 위치를 변환하는 코드는 학습 손실 계산에만 쓰며, 입력은 `query`와 `text`만으로 결정됩니다. 정답을 바꿔도 모델 입력이 같은지 별도 검사합니다.

## 비교 설계

| 조건 | 학습 자료 | 모델 입력 | 학습 출처 |
|---|---|---|---|
| 원문 | v3 기본 960행 | 원래 금액 표기 | v3 모델 3개 재사용 |
| 원문 + 문맥 보강 | v3 대상 문맥 960행 | 원래 금액 표기 | v3 모델 3개 재사용 |
| 표기 통일 | 기본 960행 | 모든 인식 금액 `0원` | 새 학습 3회 |
| 표기 통일 + 문맥 보강 | 대상 문맥 960행 | 모든 인식 금액 `0원` | 새 학습 3회 |

동일한 KLUE-RoBERTa-base의 상위 2개 encoder 층과 출력층, 근거 학습 손실, 초기값 17·42·2026을 사용합니다. 10 epoch, 300회 갱신 시도, 유효 batch 32(8씩 누적), encoder 학습률 2e-5·출력층 1e-3을 유지합니다. fp16 overflow로 실제 갱신이 생략되면 기록합니다. 마지막 epoch를 사용하며 평가로 체크포인트를 고르지 않습니다. 새 학습은 **6회**, v3의 27회와 합해 이 두 연구 단계에서 33회입니다.

행 수를 독립적인 언어 사례 수로 세지 않습니다. 금액 표기를 통일하고 대상명을 가리면 기본 학습 960행은 **120개 표현**, 문맥 보강 학습 960행은 **480개 표현**입니다. 검증 160행은 40개, 평가·복합 반례 각각 576행은 96개 표현입니다. 문맥 보강의 추가 표현도 작성한 다른 사업 구문을 조합한 것으로, 자연 문장의 독립 수집 사례가 아닙니다.

원문 조건의 6개 모델은 같은 체크포인트를 다시 불러 추론합니다. 기존 예측과의 일치도 확인하므로 새로운 학습 반복으로 세지 않습니다. 기존 코드·자료는 수정하지 않고 [잠금](freeze.json)에 의존 파일의 해시를 포함합니다.

## 무엇을 평가하는가

- 기본 평가 576행과 그 금액만 원 단위로 바꾼 576행.
- 다른 사업의 정정 부인과 금액을 덧붙인 576행.
- 위 방해 문장까지 모두 원 단위로 바꾼 **복합 반례 576행**. 새 조합 진단이지만 기존 문법과 사건을 변형한 자료입니다.
- 기존 공식 구절 12개는 별도 집계합니다. AI 임시 라벨이며 사람 정답집이 아닙니다.

공동 일치는 관계·상태·모든 금액의 역할·위치·값이 모두 맞는 경우입니다. 축별 지표, 근거 문자 F1, 학습 제외 대상 조합, 보류 후 답변율·오류·유형별 누락도 함께 남깁니다. 원문 판독과 v3의 수치 제약 판독을 각각 보고합니다. 수치 제약은 **모델이 연결한** 기준·후속 금액이 다를 때 재표현 확률을 제거하며 정답 역할을 사용하지 않습니다.

표기 통일 뒤 입력 토큰이 같아지는 쌍은 같은 예측을 해야 합니다. 이 일치율과 정답률은 다릅니다. **같은 오답을 내도 일치율은 높습니다.** 입력을 같게 만드는 설계가 제공한 성질을 모델이 수치 의미를 학습했다는 증거로 해석하지 않습니다.

복합 반례의 ‘표기 통일 + 문맥 보강’과 ‘원문 + 문맥 보강’ 차이는 세 초기값 평균의 문장별 차이를 6개 frame 묶음으로 bootstrap합니다. 동일 문법 안의 조건부 변동이며, 독립 언어·기관·사건 모집단의 신뢰구간이 아닙니다. 모든 초기값과 낮아진 지표도 공개합니다.

## 버린 정보와 남은 한계

`50만 원 → 500,000원`과 `50만 원 → 600,000원`은 같은 문맥 입력이 됩니다. 실제 값은 보관하지만 인코더는 둘을 구별할 수 없습니다. [같은 입력·다른 값 예시](data/value_information.json)는 이 정보 손실을 보여 줍니다. 수치 제약 하나로 크기·방향·비율·비교 범위 이해를 모두 복원할 수는 없습니다.

파서는 아라비아 숫자로 쓴 원화에 한정됩니다. 한글 수사, 음수, 범위, 외화·비율 등을 온전히 해석하는 파서가 아닙니다. 인식 누락이나 잘못된 경계는 표기 통일에도 영향을 줍니다. 이번 수치 보존 검사는 사용한 구절과 지원하는 표기 안에서의 결과입니다.

이 연구는 v3의 실패를 본 뒤 설계한 **사후 연구**입니다. 기존 평가·공식 구절은 이미 관측한 자료입니다. 문서 전체의 화자·부정 범위, 실제 공고 두 버전 연결, 새 기관·사건 평가와 독립 2인 판독은 여전히 남아 있습니다. 사람 판독 완료는 0건입니다. 기존 [108개 독립 판독 양식](../policy_reading_v3/annotation/GUIDE.md)을 보존합니다.
