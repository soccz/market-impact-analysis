# 문장이 바뀐 뒤, 누구의 판단이 바뀌는가

정책 뉴스 개발에서 시작한 개인 NLP 연구를 **정책 버전의 조건·예외·적용 결론**으로 확장한 첫 실제 문서 사례입니다. 기존 v1–v5의 금액·관계·상태·근거 추출 실험은 보존합니다. 이 사례는 새 모델의 성능 향상이 아니라, 앞으로 추출 모델이 맞혀야 할 의미 단위와 검증 방법을 구체화한 작업입니다.

> 연구 질문: 지원금 상한이 같아도, 조건의 변화가 서로 다른 사람에게 반대 방향의 결론을 만들 수 있는가?

## 이번에 실제로 한 일

서울시 공고 **2022-2542(2022.9.6.)**와 **2023-1362(2023.5.8.)**의 전체 첨부를 읽고, 주거 조건과 특정 복지급여 제외 조건을 출처 위치에 연결했습니다. 두 문서는 연도별 사업 공고이며 오기 정정 전후 쌍이 아닙니다. 서울경제 관련 비공개 자료·납품 구현·실제 신청자 정보는 사용하지 않았습니다.

두 공고의 지원 상한은 40만원이지만, 다음 두 변화는 방향이 다릅니다.

| 선택한 조건 | 2022년 공고 | 2023년 공고 |
|---|---|---|
| 주거 | 보증금 5천만원 상한, 월세 기본 조건과 환산 예외 | 거래금액 2억원 이하, 작은 거래금액의 별도 환산 |
| 해당 급여 제외 | 주거급여; 생계·의료·교육급여에는 신청 가능 단서 | 생계·의료·주거급여를 제외 목록에 명시 |

출처: [2022년 공고 첨부](https://www.gangnam.go.kr/file/1/get/ea599d5c-8fec-46af-b19d-08b70c2cb2f8/download.do), [2023년 공고 PDF 3쪽](https://youth.seoul.go.kr/resource/file/conts015_1.pdf). 출처 URL·공고번호·수집 시각·원본 SHA-256·짧은 구절·위치는 [sources.json](sources.json)에 있습니다. 현재 게시물의 첨부 표시와 실제 반환 파일이 다른 경우도 기록했습니다.

**결과는 선택한 두 조건의 판독입니다.** 나이·소득·건강보험료·이사일·거주지·소유·중복 지원·지출 종류·예산·우선순위 등은 계산하지 않습니다. 동일한 가상 입력을 두 규칙에 대입하는 통제 비교이며, 한 사람의 실제 연도별 자격·지원금·수혜 변화가 아닙니다.

## 문장 판독에서 조건 실행으로

1. **원문 → 조건 표현:** 조건을 수동으로 형식화하고 원문 위치를 연결했습니다. AI 지원 작성이며 자동 규칙 추출기가 아닙니다.
2. **조건 → 사례 판독:** 충족 / 미충족 / 확인 필요를 구분합니다. 모르는 보증금을 0으로 채우거나, 없는 근거를 조건 철회로 바꾸지 않습니다.
3. **판독 → 변경 원인:** 두 조건 묶음 중 어느 것을 새 버전으로 바꾸면 결론이 뒤집히는지 모든 부분집합을 계산합니다. 포함관계상 최소 집합을 제시하며 실제 정책 효과의 인과 추정은 아닙니다.
4. **해석 분기 → 보류:** 2022년 환산 문구를 1천원 단위 내림으로 해석한 후보와 공고의 구간표를 별도로 실행합니다. 두 판독이 다르면 임의로 해결하지 않습니다. 공식 문서가 잘못됐다는 판정도 아닙니다.

예를 들어 보증금 3천만원·월세 45만원 사례는 두 버전의 주거 조건을 충족합니다. 옛 예외를 삭제한 통제에서는 이를 새로운 포함으로 오인합니다. 같은 주거 조건에 생계급여 수급을 추가하면, 새 제외 목록 때문에 선택 조건의 결론이 반대로 바뀝니다.

## 실행 결과와 재현

[결과 보고서](results/RESULTS.md), [전체 1,360개 가상 조합과 원시 추적 JSONL](results/grid.jsonl), [CSV](results/grid.csv), [14개 설명 사례와 근거 가리기 결과](results/scenarios.json), [프로토콜](protocol.json).

```bash
cd research/policy_semantic_diff
python3 -m unittest -v test_engine.py
python3 run.py --output /tmp/policy-semantic-diff-replay
python3 verify.py
```

실행에는 Python 표준 라이브러리만 필요합니다. 산출물에 입력 코드·자료 해시를 기록합니다. `results/`의 다섯 산출물과 새 출력의 바이트를 비교할 수 있습니다. 원본 전체 첨부는 재배포하지 않으며 공개 데이터는 새로 작성한 조건·가상 입력·실행 결과입니다.

실제 정책은 **1개**, 공고 쌍은 **1개**, 독립 사람 검수는 **0명**입니다. 1,360개 조합을 실제 사례 1,360개나 NLP 정확도로 보고하지 않습니다. 자료 선정과 경계값 설계는 탐색적이며 사전등록·블라인드 평가가 아닙니다. 두 제거 실험도 같은 수동 형식화를 기준으로 하는 민감도 분석입니다.

## 다음 NLP 실험이 풀어야 할 문제

| 연구 가설 | 이번에 마련한 관측 방법 | 아직 입증하지 않은 것 |
|---|---|---|
| 문장 유사도보다 조건 구조가 적용 변화에 민감하다 | 같은 금액·다른 조건의 양방향 반례와 예외 제거 | 자동 추출 모델이 실제 문서에서 우월한지 |
| 기관의 정정 명칭과 실질 적용 변화는 별도 축이다 | 이 쌍을 연도별 변경으로 표시; 정정으로 재명명하지 않음 | 진짜 정정 공고에서도 두 축이 다른 사례의 빈도 |
| 요약에서 빠진 조건을 삭제로 읽으면 변경을 과대 추정한다 | 옛 예외를 제거했을 때의 판독 변화 | 기사·요약 전체의 자동 의미 보존 판독 |
| 부족한 근거의 종류가 다음 확인 질문을 결정한다 | 입력 미확인·근거 가림·해석 분기 사유 | 사람 검토 시간 절감, 질문 우선순위 최적화 |
| 본문이 같아도 참조 별표의 변경으로 결론이 바뀐다 | 현재 사례의 출처 위치 연결 | 실제 별표 버전 쌍 수집과 자동 의존 관계 추출 |

자동화의 평가 단위는 **문서 쌍 → 조건·예외·범위 → 원문 근거 → 사례별 결론**입니다. 각 단계 오류를 따로 세어, 실행기가 잘 돌아간다는 사실을 한국어 이해 능력으로 바꾸어 주장하지 않습니다. 새 사건을 잠근 뒤 독립 판독과 조건 추출 기준선을 비교해야 합니다. 현재 [빈 사람 판독 양식 28행](human_review_blank.csv)은 완료된 검수가 아닙니다.
