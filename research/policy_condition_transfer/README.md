# 새 공고에서 고정 판독기의 첫 적용

8개 서울 공고를 보고 보완한 판독기를 수정하지 않고 **2025년 공고 4개**에 처음 적용했습니다. 기존 사업의 후속 연도 2개와 새 지역·사업 2개입니다. 기존 보완판은 판독 가능한 13항목 중 **값+필요 근거 4개 / 기본값만 일치 3개 / 보류 6개**였습니다. 이전 30/30은 관측 자료에 대한 적합이었으며 새 문서의 성공을 보장하지 않았습니다.

2026-10-01 · soccz 개인 후속 연구 · AI 지원 잠정 판독 · 독립 사람 검수 0 · 새 모델 학습 0.

## 무엇을 고정했나

[프로토콜](protocol.json)과 이전 판독기 코드를 자료 검색 전에 [해시로 고정](freeze.json)했습니다. 서울 월세·문화패스, 경기 면접수당 1차, 부산 디딤돌카드 초기 공고라는 네 수집 대상을 고정했습니다. 예측 결과를 보고 문서를 교체한 건 없습니다. [수집 실패 및 제외 기록](collection_log.json)과 [원본·canonical 텍스트 해시](sources.json)를 남겼습니다.

[추론 코드](infer.py)는 이전 reader/refined를 그대로 가져옵니다. 새 예측을 저장하고 [해시 잠금](results/prediction_lock.json)을 만든 뒤 원문에서 잠정 기준을 작성했습니다. 예측을 표시하지 않고 저장한 시점에는 새 reference 파일이 없었습니다. 검색 요약과 원문 식별 과정에서 내용을 봤으므로 블라인드 평가나 외부 사전등록으로 부르지 않습니다.

**범위:** 4공고 × 나이·명시 출생일·중위소득 상한·네 기초생활급여 제외 = 16항목. 13항목은 명시 기준이 있고, 3항목은 선택된 첨부 안에서 기준을 확정하지 않았습니다. 완전한 신청 자격 판정, 소득/보험료 환산, 인구 영향, 실제 정정 전후 평가는 아닙니다.

| 문서 순서 첫 추출 | 6 | 2 | 5 | 0 |

| 기존 보완판 고정 | 4 | 3 | 6 | 0 |

별도 미확인 3항목은 모든 방법이 보류했습니다. 이 보류를 13항목의 성공에 더하지 않습니다. 다른 값 0은 오류율 0을 뜻하지 않습니다. 답해야 할 항목을 보류하거나 예외 근거를 빠뜨렸습니다. 숫자만 맞힌 경우와 조건의 적용 범위를 읽은 경우를 구분합니다. 고정 KLUE 평균 표현은 검색 학습 없는 기준선으로, 생성형 모델 전체의 성능을 대표하지 않습니다.

## 어떤 실패가 다음 연구를 바꿨나

- **PDF 표면 순서:** 서울 월세의 급여 제외는 원문에 있습니다. 공백 제거·좌표순 추출에서 괄호 위치가 달라져 기존 정규식이 놓칩니다. 시각 원문 5쪽과 추출 문자열을 대조했습니다.
- **범위 없는 정답:** 서울 문화패스의 일반 연령·출생일은 읽지만, 의무복무 제대군인의 복무 기간별 세 갈래 확장은 반환한 근거에 없습니다. 20–23이라는 기본값 일치만으로 전체 조건을 맞혔다고 세지 않습니다. 출생연도 확장을 임의의 전체 날짜 구간으로 바꾸지도 않았습니다.
- **부분 대상 근거:** 같은 문화패스에서 보완판의 소득 수치는 맞지만 재수혜자의 두 연도 중 앞 연도 표지가 근거에서 빠집니다. 지원 범위 전체를 뒷받침한 것으로 채점하지 않습니다.
- **표현과 구역 의존:** 경기의 이상/이하 연령 표현은 범위 기호만 찾는 파서가 놓칩니다. 부산의 자격 요건 제목은 고정 구역 탐색과 맞지 않아 보완판이 네 항목 모두 보류합니다. 첫 추출은 나이만 읽습니다. 날짜 옆 표현, 소득 괄호, 급여의 허용·제외 문장도 기존 파서의 범위를 벗어납니다.
- **입력 경계:** 경기 공고 본문은 별도 FAQ를 가리킵니다. 선택한 PDF 안에 소득 제한 없음이라는 명시 문구가 없어 미확인으로 뒀습니다. 외부 검색 요약을 몰래 합치지 않았습니다. 미언급과 무제한을 구분하는 테스트는 추가했지만, 실제 무제한 사례를 검증했다고 주장하지 않습니다.

## 채점 주석과 정직한 수정 기록

나이·출생일의 일반 구간 값은 기존 표현으로 유지하고, 명시된 병역 정의·분기 전체가 있어야 공동 성공으로 세었습니다. 이 분기별 주석 방식은 **원문을 읽은 뒤, 예측을 보기 전에** 정했습니다. 프로토콜에 분기별 형식까지 사전 명시한 것은 아닙니다. `value_only`는 기본값 수치 일치이며 완전한 의미 표현이 아닙니다.

최초 채점 후 서울 월세 소득 문단에 반복된 동일 기준의 두 번째 위치를 주석에서 빠뜨린 것을 확인했습니다. [최초 기준과 채점](audit/initial_annotation/)을 보존하고 [주석 정정](annotation_erratum.json)으로 같은 문단의 동등한 근거를 추가했습니다. KLUE 공동 성공만 2→3으로 바뀌었습니다. 예측·값 라벨·판독기·문서는 바꾸지 않았습니다. 따라서 최초 계획의 단 한 번 채점과 다른 부분을 공개하며 완전한 블라인드 벤치마크라고 주장하지 않습니다. [최초 주석 작성 기록](annotation_record.json)

이전 30항목과 이번 13항목은 문서·범위 조건이 다릅니다. 30/30과 4/13을 같은 표본의 성능 감소율로 계산하지 않습니다. 네 문서는 목적에 따라 선택한 소규모 첫 적용이며 모집단 일반화나 유의성 주장을 하지 않습니다.

## 재현과 사람 판독

의존성은 [기존 고정 환경](../policy_condition_reading/requirements.txt)을 사용합니다. `sources.json`의 원문을 외부 캐시에 `<id>.bin`으로 저장합니다. 공개 저장소에 첨부 원본·전체 추출문·고객 자료는 없습니다. 부산은 발행기관의 옛 주소/TLS 문제로 대학이 배포한 같은 날짜의 공고 첨부를 사용했으며, 발행기관 원본과 별도 사본의 해시 일치를 확인한 것은 아닙니다.

```bash
python3 research/policy_condition_transfer/verify.py --cache /path/to/private-cache
python3 research/policy_condition_transfer/infer.py --cache /path/to/private-cache --model /path/to/locked-klue-snapshot --output /tmp/condition-transfer-replay
python3 research/policy_condition_transfer/evaluate.py --output /tmp/condition-transfer-scores
```

원본 결과를 덮어쓰지 않고 별도 출력 디렉터리를 사용합니다. CPU 재실행의 `predictions.json`이 최초 파일과 바이트 단위로 같은지 확인합니다. 4개 평가 경계 테스트, 근거 offset/hash, 이전 고정 코드와 이전 674개 산출물, 주석 전·후 잠금 순서를 검사합니다. 학습·캐시·원문 위치는 사용자의 환경에 맞춰 지정합니다.

[독립 판독용 빈 16행](human_review_blank.csv)은 아직 채워지지 않았습니다. 실제 검토자가 원문을 보고 적용 대상·예외·근거를 독립 기입한 뒤 불일치를 조정해야 합니다. AI 재검사는 사람 판독 수에 포함하지 않습니다.

## 다음 검증의 단위
