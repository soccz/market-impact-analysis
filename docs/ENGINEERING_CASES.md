# 네 가지 구현 사례 — 코드를 통해 판단을 읽기

[전체 업무 지도](WORKSTREAMS.md) · [시간순 과정](DEVELOPMENT_JOURNEY.md) · [홈페이지의 실행 사례](https://soccz.github.io/projects/market-impact-v2/#engineering)

2026년 9월에 만든 설명용 예제입니다. 실제 기사·가격·판독 파일을 사용하지 않습니다. **합의 사례는 기존 공개 스크립트를 수정 없이 실행**합니다. 날짜·커버리지 사례는 원리를 설명하기 위해 새로 작성한 계산이며 고객 분석의 재현이나 실제 모델 성능이 아닙니다.

```bash
python examples/engineering_demo.py --check
python examples/engineering_demo.py
```

Python 표준 라이브러리만 사용합니다. 모델·네트워크가 필요 없고, 합의 스크립트의 고정 상대경로는 임시 디렉터리에 만든 가상 파일로 충족합니다. 실제 작업 파일에 쓰지 않습니다.

[홈페이지의 시각 예제](https://soccz.github.io/projects/market-impact-v2/#case-comparison)에서는 시작 가격을 그래프에서 선택하고, 포함 정책을 행렬과 같은 축의 막대로 대조할 수 있습니다. 모든 수치는 위 명령의 합성 출력과 일치합니다.

## 1. 라벨 처리와 재검토 큐

학습 입력을 만들기 위해 복수 판독의 답뿐 아니라 확신도·근거를 연결하고 재검토 대상을 분리하는 도구를 구현했습니다. [원본 합의 코드](https://github.com/soccz/market-impact-analysis/blob/5193cbb/v2/code/train500/build_train_500_consensus.py)의 main을 별도 Python 프로세스로 실행합니다. 입력의 관련성 값은 모두 같게 두고 입장·확신도·파일 누락 조건을 바꿉니다.

| 합성 상황 | 원본 상태 | 재검토 큐 | 해석 |
|---|---|---|---|
| 세 판독이 같으면 | `unanimous` | 미포함 | 후보: `support` |
| 다수결과 확신이 확보되면 | `majority_auto` | 미포함 | 후보: `support` |
| 다수결이어도 저확신이면 | `needs_review_low` | 포함 | 후보: `support` |
| 세 판독이 모두 다르면 | `needs_review_split` | 포함 | 후보: `없음` |
| 모두 저확신인데 일치하면 | `unanimous` | 미포함 | 후보: `support` |
| 한 판독 파일에 행이 없으면 | `absent_from_output` | 미포함 | 후보: `없음` |

`absent_from_output`은 원본이 저장한 상태값이 아니라, 출력에 행이 없음을 이번 예제에서 표시한 이름입니다.

입력 ID의 합집합은 6개, 원본 결과는 5행, 재검토 큐는 2행입니다. 다음 두 가지는 원본의 한계로 함께 확인합니다.

- **모두 저확신인데 일치하는 경우:** 만장일치 조건이 먼저 적용돼 자동 처리됩니다. 저확신을 항상 보류하는 규칙은 아닙니다.
- **판독 파일 한 곳에 행이 없는 경우:** 원본은 세 파일의 ID 교집합을 사용하므로 결과에도 재검토 큐에도 남지 않습니다. 입력 합집합과 출력의 대조가 별도로 필요합니다.

저확신 다수결에서는 `support` 후보가 채워져도 재검토 상태입니다. 값이 존재하는 것과 사람이 확인한 정답은 다릅니다. 이번 문서는 과거 합의 코드를 수정하거나 실제 판독을 확정하지 않습니다. 실행 JSON에는 사용한 원본 파일의 SHA-256도 남깁니다.

## 2. 배치 추론의 처리 구조

[공개 배치 실행기](https://github.com/soccz/market-impact-analysis/blob/5193cbb/v2/code/run_ptei_full_inference_batched.py)를 보면 다음 단계를 구분할 수 있습니다.

1. 입력 행별 관련성·일치 근거와 원래 위치를 보존합니다.
2. 관련성이 확인된 행에서 카드의 활성 채널과 키워드를 확인합니다.
3. hybrid 설정이면 모아 둔 후보의 임베딩을 배치로 계산해 의미 gate를 추가합니다.
4. 관련성이 있고 활성 채널이 있는 행을 정책별 NLI 작업으로 묶습니다.
5. 정책별 공통 가설로 계산한 점수를 입력 행 위치에 연결하고 중간 판정과 함께 출력합니다.

`embed_jobs`, `nli_jobs`, `meta`, `indices`가 처리 대상과 결과 위치를 연결합니다. 정책별 가설이 다르므로 단순히 모든 기사 문자열을 한 배열로 합쳐 모델에 넘기는 문제로 끝나지 않습니다.

**읽을 때 주의할 실제 동작:** `stance_scores`의 초기값과 `pred_stance`는 neutral입니다. 추론에 들어가지 않은 행도 그 기본값을 가질 수 있어 모델의 판정과 실행 제외 상태를 구분해야 합니다. 원본이 독립 실행 상태 열을 충분히 제공한다는 주장이나, 이 회고에서 속도·메모리·추론 정확도를 재측정했다는 주장은 하지 않습니다.

후속 실행기에는 번역 경유 감성 분석, 장치 선택, 중간 저장·재개가 구현돼 있습니다. 저장된 행 수만 확인하는 재개 조건 등 한계도 있어 입력 버전까지 보장하는 완전한 복구라고 설명하지 않습니다. 후속 소스와 고객 설정은 공개하지 않습니다.

## 3. 날짜와 커버리지로 달라지는 비교

후속 비교 코드는 뉴스 날짜를 거래일 가격에 연결하고, 정책별 비율을 먼저 구한 뒤 같은 비중으로 집계합니다. 서로 다른 버전의 시작일 규칙, 모델별 입력 단위와 가용 범위가 함께 관리돼야 했습니다.

### 날짜 예제 — 시작점을 바꾸면 부호도 바뀐다

가상 뉴스일은 2026-07-07, 고정 종료일은 2026-07-10입니다. 가상 가격은 7/7에 100, 7/8에 120, 7/10에 110입니다.

| 시작 규칙 | 가격 구간 | 수익률 |
|---|---|---|
| 같은 날 또는 이후 첫 관측일 | 100 → 110 | +10.00% |
| 뉴스일보다 뒤의 첫 관측일 | 120 → 110 | −8.33% |

종료 가격을 고정했는데도 부호가 바뀝니다. 날짜만 있는 뉴스는 장중·장후 정보의 이용 가능 시점을 확인해 주지 않습니다. 종료일 이후의 가격이 없거나 유효한 비교 구간이 없으면 함수는 `None`을 반환합니다. 미래 가격을 마지막 관측값이나 0%로 대체하지 않습니다. 비거래일 입력과 마지막 관측일 이후 입력도 검증합니다.

### 커버리지 예제 — 같은 정책으로 좁히면 순위가 바뀐다

정책별 비율을 X={A:90, B:90}, Y={A:95, B:95, C:10, D:10}으로 만든 합성 사례입니다.

| 범위 | X의 평균 / 커버리지 | Y의 평균 / 커버리지 |
|---|---|---|
| 각 모델의 가용 정책 | 90.0% / 2/4 | 52.5% / 4/4 |
| 공통 A·B 정책 | 90.0% / 2/4 | 95.0% / 2/4 |

가용 표본 전체와 동일 표본의 비교는 답하는 질문이 다릅니다. 공통 표본에서 Y가 높아도 빠진 정책에서 X의 결과를 알게 되는 것은 아닙니다. 예제의 비율은 어떤 실제 모델의 정확도도 아닙니다. [기존 분모 예제](https://soccz.github.io/projects/market-impact-v2/#aggregation-demo)와 함께 날짜·표본·가중 방식의 영향을 구분할 수 있습니다.

## 4. 결과 생성과 전달 검수

후속 작업에는 그래프 외에 발표 HTML·PDF, 문서형 보고서, CSV·JSON과 연동 설명을 생성하는 코드가 있습니다. 모델별 구획, 표 분할, 인쇄 레이아웃, 표시명·축·정의의 일치를 다루는 일도 개발 범위에 포함됩니다.

검토용 사본을 만드는 처리와 사본의 수치 필드를 비교하는 검증을 구분했습니다. 다음 세 질문은 서로 다른 증거가 필요합니다.

| 질문 | 확인 대상 | 이것만으로는 확인할 수 없는 것 |
|---|---|---|
| 어떤 자료·정의로 계산했나 | 원천 버전, 키 연결, 시점과 판독 기준 | 파일 해시만으로 원천 정확성 판단 |
| 표·차트·설명이 일치하나 | 수치 필드, 표시명, 허용한 비교 구간 | 정상 렌더링만으로 내용 정확성 판단 |
| 전달 파일이 검토본과 같은가 | 파일 목록·크기·해시, ZIP과 디렉터리 대응 | 패키지 일치만으로 사람 확인·인수 완료 판단 |

일부 과거 검증기에는 당시 기대값이 고정돼 있고, 이후 원천 감사에는 보완할 항목이 남습니다. 따라서 이번 기록은 검수 도구와 점검 작업의 구현을 설명하며 모든 검증의 통과나 공식 인수를 선언하지 않습니다.

## 이번에 실제로 확인한 것

공개 합의 프로그램을 합성 파일로 실행한 결과, 날짜 규칙의 경계조건, 커버리지 변경에 따른 평균, 문서와 홈페이지의 표시 결과를 대조했습니다. 과거 전체 코퍼스의 모델 추론·학습·시장 분석은 재실행하지 않았습니다. 재현 가능한 작은 동작과 전체 연구 검증의 범위를 구분합니다.
