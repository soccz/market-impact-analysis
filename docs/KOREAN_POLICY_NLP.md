# 한국어 정책 문장의 사실·정정·내용 변화 판독

soccz의 2026년 9월 개인 후속 연구 기록입니다. 기존 정책 뉴스 개발에서 만난 **반복 보도·정정·시간·판독 불확실성**을 문장 수준의 NLP 과제로 좁혔습니다. 고객 원자료와 납품 구현을 쓰지 않고 공개 모델·공개 벤치마크·새 합성 자료로 실행했습니다. 설계·구현·합성 예문·분석에는 AI 지원을 사용했습니다. 독립적인 사람 판독은 아직 수행하지 않았습니다.

## 질문이 바뀐 과정

1. **문장이 주장을 지지하는가?** 작은 NLI 진단에서 단위 규칙으로 맞힌 사례가 늘었지만, 새 반례에서는 부정과 총액·삭감액의 범위를 놓쳤습니다. 작은 성공 사례에 맞춘 규칙을 채택하지 않았습니다.
2. **정책 대비 예문을 학습하면 일반화하는가?** 한국어 모델을 세 초기값으로 실제 학습하고, 동일 출발점·학습량의 비교 조건을 만들었습니다. 합성 점수는 올랐으나 공식 문서 사례에서는 개선되지 않았습니다.
3. **숫자가 어려운가, 표현이 어려운가?** 단위 정규화와 표현×내용 요인을 따로 조사했습니다. 같은 내용을 다른 문장으로 적었을 때 성능이 크게 떨어졌습니다.
4. **무엇이 달라졌는지 근거까지 뽑을 수 있는가?** 단일 NLI 점수를 넘어 금액의 이전값·현재값·기타 역할과 ‘오기 정정 / 정책 변경 / 동일 금액 / 관계 불명’을 분리했습니다.
5. **틀릴 때 보류하면 충분한가?** 높은 확신으로 답한 비율과 오류뿐 아니라, 정작 정정·변경에 답했는지를 확인했습니다. 합성 자료의 오류 0건만으로 실제 정책 판독의 신뢰성을 설명할 수 없었습니다.

NLI의 ‘모순’은 두 문장의 관계입니다. **정정이 있었는지, 정책을 실제로 바꿨는지, 계획이 확정됐는지**는 추가 근거가 필요한 별도 질문입니다.

## v1 — 실제 모델 학습과 원인 진단

[고정 프로토콜](../research/nli_v1/protocol.json), [전체 집계](../research/nli_v1/analysis.json), [사후 탐색](../research/nli_v1/followup_analysis.json), [기록·해시](../research/nli_v1/research_record.json)를 공개합니다. 전체 학습 가중치·원시 예측은 로컬에 보존했으며 이 공개 묶음만으로 v1 전체 학습을 재현할 수 있다고 주장하지 않습니다.

- KLUE-NLI v1.1 공식 train 24,998개에서 근거 문장 단위로 학습 22,423 / 내부 검증 2,575를 분리했습니다. 공식 dev 3,000개는 별도 평가이며 숨겨진 test가 아닙니다.
- `klue/roberta-base`를 seed 17·42·2026으로 2 epoch 전체 미세조정했습니다. 각 모델에서 동일한 240 step 추가 학습: 일반 문장 32개 대 일반 16 + 정책 16개입니다. 마지막 체크포인트를 고정했습니다. 총 9개 체크포인트를 보존했습니다.
- 합성 정책 문장 학습 1,728 / 검증 432 / 평가 864쌍. 9개 현상, 같은 주장에 지지·불충분·모순을 하나씩 배치했습니다. 작성자가 문법과 방법을 모두 설계했으며 사람 정답집이 아닙니다.

| 평가 | 일반 문장 추가 학습 | 정책 문장 혼합 | 해석 |
|---|---:|---:|---|
| 합성 정책 864쌍, 3 seed 평균 | 43.90% | 60.22% | +16.32%p; 288묶음 bootstrap 95% 구간 [13.77, 18.94]%p |
| KLUE 공식 dev 3,000쌍 | 84.57% | 84.83% | +0.27%p; 구간 [-0.21, 0.76]%p |
| 공식 문서 6개에서 만든 임시 라벨 18쌍 | 74.07% | 74.07% | 평균 개선 없음; 선택된 소규모 사례 |

구간은 구성한 데이터와 관측한 3개 초기값에 조건부입니다. 표현·사람 판독·모집단·전체 초기값 변동까지 포함하지 않습니다. 정책 혼합 모델의 seed별 합성 정확도는 66.90 / 56.13 / 57.64%로 차이가 큽니다.

사후 2×2 비교에서는 동일한 미관측 값 범위를 사용하고 표현만 바꿨을 때 **83.90 → 61.27%**였습니다. 각 조건 735쌍이며 원래 864쌍과 구성도 다릅니다. 단위만 정규화한 탐색에서는 합성 점수가 60.22 → 65.08%로 올랐지만 공식 18사례는 그대로였습니다. 이때 원문·변환문을 모두 fp32·동일 배치로 다시 비교해 추론 정밀도에 따른 뒤집힘을 통제했습니다. 두 탐색 모두 이미 관측한 자료의 원인 진단입니다.

## v2 — 관계와 금액 역할을 분리하는 실행 가능한 실험

[프로토콜](../research/policy_revisions/protocol.json)과 [입력·코드 잠금](../research/policy_revisions/freeze.json)을 첫 모델 학습 전에 저장했습니다. 문자 모델의 결과를 본 다음 한국어 사전학습 표현을 비교했으므로 **문맥 모델과 입력 통일 비교는 사후 탐색**입니다. 모든 조건과 실패를 남겼습니다.

입력은 짧은 정책 금액 안내문입니다. 통화 구절을 파싱하고, 관계를 분류하고, 각 금액 구절의 역할을 학습합니다. 모델에는 원문만 전달합니다. 생성 규칙의 정답이나 역할 메타데이터는 추론에 전달하지 않습니다. 반환한 금액은 원문의 시작·끝 위치와 원 단위 환산값에 연결됩니다. 대상·시간·시행 상태를 모두 자동 추출한 시스템은 아닙니다.

| 자료 | 문장 수 | 숫자·사업명을 가린 뒤 서로 다른 표현 | 표현 묶음 |
|---|---:|---:|---:|
| 학습 | 2,048 | 40 | 4 |
| 검증 | 256 | 20 | 2 |
| 평가 | 768 | 40 | 4 |

숫자만 바꾼 예문을 독립적인 언어 사례로 세지 않습니다. 평가 768개는 표현 40개의 반복이므로 **대규모 한국어 일반화 평가로 해석하면 안 됩니다.** 인위적 사업명·연도·값 범위와 표면 문장은 분리했으나, 같은 작성자의 규칙과 의미 구성을 공유합니다. 사례 단위 bootstrap도 이 좁은 구성 안의 변동만 표현합니다.

‘관계 불명’은 입력이 정정·변경 등을 확정하지 않는다는 의미 라벨입니다. 모델이 확신 부족으로 출력을 보류하는 것과 다릅니다. 관계 불명 예문에는 사유 미기재, 부인, 조건문, 검토 중인 제안이 포함됩니다. 공식 문서의 계획·확정 구분에는 해석 여지가 있어 독립 판독이 필요합니다.

### 무엇을 실제로 비교했나

| 방법 | 관계 분류 정확도 | 관계+금액 역할·위치·값 모두 일치 |
|---|---:|---:|
| 단어 규칙 + 등장 순서 기준선 | 73.44% | 23.44% |
| 문자 TF-IDF 관계 + 근처 문맥으로 역할 학습 | 59.38% | 28.13% |
| 입력 정규화를 문맥 모델과 맞춘 문자 비교 | 59.38% | 25.00% |
| 고정 KLUE-RoBERTa 관계 + 등장 순서 | 71.88% | 31.25% |
| 고정 KLUE-RoBERTa 관계 + 금액 토큰 문맥 | 71.88% | **50.00%** |

마지막 두 줄은 동일한 관계 예측을 사용합니다. 금액을 등장 순서 대신 문맥 표현으로 연결했을 때 **공동 일치가 18.75%p 개선**됐습니다. 모두 자동 판독 정답이 구성 규칙과 얼마나 맞는지를 측정한 결과입니다. 문자 방식과 문맥 방식은 특징·정규화·분류기 규제가 달라 단일 요소의 인과 효과로 보지 않습니다. 입력 통일 비교를 추가해 정규화 차이도 별도로 확인했습니다.

문맥 모델은 공개 `klue/roberta-base`의 가중치를 **고정**하고, 문장·금액 토큰 표현 위에 로지스틱 회귀를 학습했습니다. CPU에서 실행했으며 v1처럼 신경망 전체를 추가 학습한 것이 아닙니다. 숫자를 가린 반복 문장을 중복 계산하지 않아 합성 100개 표현과 공식 5개 구절, 총 105개를 인코딩했습니다.

### 답변율을 낮추면 핵심 과제도 사라졌다

검증에서 공동 오류 5% 이하를 만족하는 가장 넓은 응답 범위를 선택했습니다. 문자 모델은 검증에서 오류 0건이었지만 평가 응답의 **57.14%가 틀렸습니다**. 검증 분포에서 고른 기준이 새 표현의 오류를 보장하지 않습니다.

문맥 모델의 선택 기준은 0.95였습니다. 평가 768개에서:

- **132개 답변 / 636개 보류**, 답변율 17.19%, 답한 것 중 관측 오류 0개.
- 정정 192개 중 **0개**, 정책 변경 192개 중 **0개** 답변.
- 같은 금액 48개와 관계 불명 84개만 답변.

따라서 이를 ‘정정 판독 정확도 100%’라고 부를 수 없습니다. 핵심 과제의 답변율이 0이기 때문입니다. **유형별 답변율·공동 오류·보류를 함께 보고하는 평가**가 다음 설계의 기준입니다.

### 공식 문서에서 다시 드러난 한계

[출처·짧은 인용·임시 판독](../research/policy_revisions/data/official_cases.jsonl), [전체 예측](../research/policy_revisions/results/encoder/official_cases_predictions.json)을 공개했습니다. 5개는 선정 사례이며 그중 4개 출처는 v1에서 이미 확인했습니다. 독립 실제 문서 시험이 아닙니다.

| 공식 사례 | 사전 정의에 따른 임시 판독 | 문맥 모델의 원예측 | 선택 기준 적용 |
|---|---|---|---|
| 인천 공사비 산출 오류 | 오기·산출 오류 정정 | 관계·금액 모두 일치 | 보류 |
| 자립수당 인상 | 정책 변경 | 관계·금액 모두 일치 | 보류 |
| 원주 상품권 발행규모 확대 | 정책 변경 | **정정으로 오판**; 금액 위치는 맞음 | **오답을 채택** |
| 영아수당 다년 계획 | 현재·이전 확정 관계 불명 | 동일 금액으로 오판; 역할도 오류 | 보류 |
| 산불 예산 미확정 제목 | 관계 불명 | 일치 | 보류 |

5개 중 공동 일치 3개, 선택 기준을 통과한 1개는 오답입니다. 영아수당은 ‘발표된 계획의 변화’라는 별도 라벨을 두면 판독이 달라질 수 있으며, 본 연구의 좁은 확정 관계 스키마로 다루기 어렵습니다. 짧은 구절을 선정한 판독이지 원문 전체의 내용·현행 정책을 확정하는 판단은 아닙니다.

## 여기서 발전시킬 연구

연구의 기여 후보는 새로운 모델 구조가 아니라, **정책의 변경을 근거에 연결하고 어려운 유형을 보류 뒤에 숨기지 않는 평가**입니다. 신규성·우월성은 확립하지 않았습니다.

1. **관계와 상태를 분리:** 정정/실제 변경, 확정/계획/부인/가정, 이전/현재/예정 값을 독립 필드로 판독합니다. 미래 계획을 단순 ‘불명’에 넣는 현재 스키마를 검토합니다.
2. **사유 구절도 추출:** 금액 두 개의 위치가 맞아도 원주 사례처럼 이유를 틀릴 수 있습니다. ‘산출 오류’, ‘편성 승인’, ‘계획’ 등의 근거 범위와 부정이 걸리는 구절을 함께 평가합니다. 현재 모델은 이유 구절을 학습해 추출하지 않습니다.
3. **사건 단위 독립 평가:** 같은 공고·재전재·후속 정정을 하나의 사건으로 묶고 기관·사건·작성 시기를 분리합니다. 같은 수치 문장을 늘리기보다 새로운 실제 표현을 확보합니다.
4. **유형별 최소 답변율:** 전체 오류 목표만으로 쉬운 유형만 답하지 못하게, 정정·변경 각각의 답변율과 누락을 보고합니다. 어떤 기준도 새 분포의 안전을 자동 보장한다고 주장하지 않습니다.
5. **독립 2인 판독과 이견 보존:** [빈 판독표](../research/policy_revisions/independent_review.csv)에 합성 평가의 서로 다른 표현 40개를 준비했습니다. 판독자는 원시 예측·생성 정답을 보기 전에 라벨·근거·모호성을 기록하고, 실제 문서에는 별도의 사건·버전 자료를 추가해야 합니다. 아직 실행한 사람 평가가 아닙니다.

## 재현과 기록

v2의 입력, 첫 실행 코드, 세 조건의 원시 예측, 지표, 잠금 해시, 학습한 선형 분류기 계수를 공개합니다. [실행 안내](../research/policy_revisions/README.md)의 명령으로 별도 출력 폴더에 재실행할 수 있습니다. 원 결과를 덮어쓰지 않도록 차단했습니다. 공개 모델은 별도 준비해야 합니다.

검증기는 원시 예측으로 관계 혼동행렬·F1·근거 일치·답변율·채택 오류를 별도로 계산하고, 금액 위치와 데이터 잠금을 확인합니다. 자료의 언어적 정답을 증명하는 검사는 아닙니다. 원자료와 납품 성과로 소급하지 않으며 실제 서비스 성능이나 법률상 권리 귀속을 주장하지 않습니다.
