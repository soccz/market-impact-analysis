# 작은 입력으로 공개 구현 읽기

2026년 9월에 추가한 설명용 예제입니다. 실제 기사·정책·기업을 사용하지 않고 공개된 `relevance_v3_1` 함수를 그대로 호출합니다. 과거 분석 코드는 수정하지 않았습니다.

## 재실행

저장소 루트에서 Python 3.9 이상으로 실행합니다. 표준 라이브러리만 사용하며 네트워크·모델 가중치·별도 데이터가 필요하지 않습니다.

```bash
python examples/methodology_demo.py --check
python examples/methodology_demo.py
```

첫 명령은 설명한 네 가지 동작을 확인합니다. 두 번째는 합성 입력·정책 규칙·점수·판정 근거와 실행한 원본 파일의 SHA-256을 JSON으로 출력합니다. 홈페이지의 예제도 같은 실행 결과에서 만들었습니다.

## 무엇을 확인하는가

가상 정책의 핵심어를 `제조지원안`, 대상 기업을 `한빛제조`로 지정합니다. 실제 정책 검색식이나 납품 설정이 아닙니다.

| 합성 입력 | 함수 결과 | 설명할 수 있는 설계 판단 |
|---|---|---|
| 제조지원안 발표, 신규 설비 투자 지원 확대 | 1.0 / `L1_primary_exact` | 정책 이름을 근거로 관련성 확인 |
| 제조지원안 철회, 신규 설비 투자 지원 취소 | 1.0 / `L1_primary_exact` | 관련성은 긍정·부정 또는 지지·반박과 다른 축 |
| 한빛제조, 신제품 생산 계획 발표 | 0.0 / `NO_MATCH`, 종목명 적중은 별도 기록 | 기업 이름만으로 정책 관련성을 승인하지 않음 |
| 생산시설을 새로 짓는 기업의 세금 부담을 낮춘다 | 0.0 / `NO_MATCH` | 같은 취지를 설명하도록 작성해도 등록 표현이 없으면 누락될 수 있음 |

마지막 문장의 '같은 취지'는 설명을 위해 사람이 정한 관계입니다. 실제 기사 정답을 독립 판독한 평가가 아닙니다. 이 네 사례로 precision·recall·일반화 성능을 추정하지 않습니다.

## 결과에서 다음 단계까지

관련성 확인은 해당 정책의 분석 후보를 구성하는 단계입니다. 이후 [score_stance](../v2/code/ptei_utils.py)는 정책 방향에 대한 지지·반박·중립 가설과 기사를 비교하고, [일별 패널](../v2/code/build_daily_ptei_panel.py)은 기사별 출력을 정책·날짜별로 모읍니다. 이 설명용 실행에서는 언어모델 추론과 일별 패널 생성까지 수행하지 않았습니다.

정책을 철회한 기사도 높은 관련성을 갖는다는 결과는 관련성 점수를 그대로 시장 호재 점수로 읽을 수 없다는 것을 보여줍니다. 표현이 바뀐 문장의 누락은 규칙을 넓히면 해결될 수 있지만, 무관한 기사까지 포함될 가능성도 함께 검토해야 합니다. 선택한 규칙의 이점과 한계를 함께 남기는 것이 이 예제의 목적입니다.
